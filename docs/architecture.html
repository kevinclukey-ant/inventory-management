Factory Inventory Management System

Architecture reference for a full-stack demo application: a Vue 3 single-page app talking over HTTP to a FastAPI backend that serves in-memory data loaded from JSON files. No database, no authentication, no build-time coupling between the two halves.

Overview

Two independently started processes. The browser loads the Vue app from Vite, and the app fetches everything it displays from FastAPI with plain axios GET requests. Global filters live in a shared composable and are serialized into query parameters on every call.

System Architecture

Three tiers, all on one machine in development. The frontend and backend share nothing except the HTTP contract; CORS is wide open (allow_origins=["*"]) so the two ports can talk during local development.

Tech Stack

Deliberately minimal. Three runtime dependencies on the client, three on the server, and no state outside process memory.

Frontend

client/
  • Vue 3.4 with the Composition API (setup() in every SFC, no <script setup>)
  • vue-router 4 in HTML5 history mode
  • axios 1.6 for HTTP
  • Vite 5 + @vitejs/plugin-vue for dev server and build
  • Hand-written SVG charts and CSS Grid layouts; no chart or UI library
  • Global styles in App.vue, scoped styles per component

Backend

server/
  • Python 3.11+
  • FastAPI for routing, validation, and OpenAPI docs
  • Pydantic 2 models as response_model on list endpoints
  • uvicorn ASGI server, run directly from main.py
  • Packaging via pyproject.toml (uv) with a requirements.txt mirror
  • One module, ~300 lines, no routers or service layer

Data & Tooling

server/data/, tests/, .claude/
  • Seven JSON fixtures loaded once at import time
  • generate_data.py regenerates the 2025 order set
  • pytest + FastAPI TestClient (40 backend tests)

  • Claude Code agents, skills, hooks, and MCP config for Playwright and GitHub

Data Flow

The path a filter change takes, from a dropdown in the header to a re-rendered chart. The same pipeline applies to initial page load, which just runs with every filter set to all.

User changes a filter in FilterBar

Four selects: Time Period (month or quarter), Warehouse (San Francisco, Tokyo, London), Category, and Order Status. Each is v-model-bound directly to a ref exported from the composable.

client/src/components/FilterBar.vue

Shared filter state updates

The refs (selectedPeriod, selectedLocation, selectedCategory, selectedStatus) are declared at module scope, so every component calling useFilters() sees the same singleton state.

client/src/composables/useFilters.js

Active view watches the refs and reloads

Views register a watch on the filter refs and call their load function, which pulls getCurrentFilters() to get a plain object. The period value is renamed to month here.

client/src/views/Dashboard.vue and siblings

api.js serializes filters into query params

Each method drops any key equal to all and appends the rest with URLSearchParams. Inventory calls send only warehouse and category; orders and dashboard send all four.

client/src/api.js

FastAPI handler applies filters in memory

apply_filters() chains list comprehensions for warehouse, category (case-insensitive), and status. filter_by_month() does substring matching on order_date, expanding quarters through QUARTER_MAP.

server/main.py

Pydantic validates the response

List endpoints declare a response_model, so any record missing a required field fails at serialization time. Summary, spending, and reports endpoints return untyped dicts.

server/main.py model classes

View stores raw data in refs, derives everything else

Raw arrays land in allOrders / inventoryItems. Computed properties then produce status counts, on-time rate, category breakdowns, and chart geometry. Nothing is recalculated until a dependency changes.

client/src/views/*.vue

Internationalisation & currency

A second, purely client-side data path
  • useI18n() holds currentLocale (persisted to localStorage) and a t() lookup over locales/en.js and locales/ja.js, with English fallback.
  • Currency is derived from locale: en renders USD, ja renders JPY via utils/currency.js.
  • Product and warehouse names are translated on the client after the API responds; the backend is locale-unaware.

Tasks & profile

Mock user state without a backend
  • useAuth() returns a computed mock user whose name, title, and task list switch with locale.
  • App.vue merges those mock tasks with apiTasks fetched from /api/tasks, then routes add/delete/toggle to either the local array or the API depending on origin.
  • See Observations: the task and purchase-order endpoints are not implemented on the server.

Component conventions

  • Options-style export with a setup() function; everything used in the template is returned explicitly.
  • Loading / error / data states are tracked as three refs and rendered with v-if / v-else-if / v-else.
  • Charts are inline SVG built from computed arrays; layouts use CSS Grid.
  • Modals are controlled by a boolean ref plus a selected-item ref in the parent, and emit close.
  • v-for keys are domain IDs (sku, month, id), never array index.

Dashboard specifics

  • Fetches summary, orders, inventory, and backlog in parallel on load and on every filter change.
  • Revenue goal is computed client-side: $800K for a single month, $9.6M when Time Period is all.
  • On-time rate and average fulfilment days are derived from expected_delivery vs actual_delivery on delivered orders.
  • Some KPIs (ordersData, fillRate) are hard-coded refs rather than API-driven.

Data Model

Each JSON file is a flat list (or, for spending, a small object of lists). Records are plain dicts in memory; the Pydantic classes describe their shape but are only enforced on the way out.

InventoryItem

inventory.json · 32 rows
  • id, sku, name, category
  • warehouse, location
  • quantity_on_hand, reorder_point
  • unit_cost, last_updated

Low stock = quantity_on_hand <= reorder_point. No time dimension, so month filters never apply.

Order

orders.json · 250 rows across 2025
  • id, order_number, customer
  • items[] {sku, name, quantity, unit_price}
  • status, warehouse, category
  • order_date, expected_delivery, actual_delivery
  • total_value

Status ∈ Delivered, Shipped, Processing, Backordered. Dates are ISO strings; month filtering is substring matching on order_date.

DemandForecast & BacklogItem

demand_forecasts.json · 9, backlog_items.json · 4
  • item_sku, item_name, current_demand, forecasted_demand, trend, period
  • order_id, item_sku, quantity_needed, quantity_available, days_delayed, priority

Backlog responses add has_purchase_order by scanning purchase_orders.json, which is currently an empty list.

Spending

spending.json · 3 keys
  • spending_summary {procurement, operational, labor, overhead + *_change}
  • monthly_spending[12]
  • category_spending[4]

transactions.json · 56 rows

Observations

Things worth knowing before changing the code. None are blockers for a demo, but each shapes what a feature change touches.

Six client API methods have no backend. Tasks (GET/POST/PATCH/DELETE /api/tasks) and purchase orders (/api/purchase-orders) are wired in api.js, App.vue, and the Dashboard PO modal, but main.py defines no handlers. The client catches the 404s and logs to console, so the UI stays up but those features silently no-op. purchase_orders.json and the PurchaseOrder Pydantic models exist, suggesting the endpoints were planned.
Date filtering is string matching. filter_by_month() checks month in order_date, which works for the current ISO format but would break on any other date shape. Quarter logic is duplicated between QUARTER_MAP and the reports handler.
Data is mutable module state. Lists are loaded once at import and shared across requests. Any future write endpoint will mutate them in place and lose changes on restart. The backlog handler already copies dicts before adding a field, which is the right pattern.
Reports bypasses api.js. Reports.vue calls axios.get with a hard-coded URL instead of going through the shared client, so it will not pick up any base-URL or interceptor changes made there.
Frontend is the heavy side. The backend is ~300 lines; the Dashboard view alone is over 1,200. Most business logic (goal calculations, on-time rates, category rollups, currency conversion) lives in Vue computed properties, not in the API.
Environment quirks on this machine. uv is not installed, so the backend runs from a plain server/.venv. Santa blocks the native esbuild binary, so node_modules/esbuild was swapped for esbuild-wasm without saving to package.json; a future npm install will undo that.
